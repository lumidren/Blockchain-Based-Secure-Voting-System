# VeriVote Threat Model

This document states what VeriVote defends against, how, and what it does **not** defend against. Each
mitigation points at the code that enforces it (`path:line`). Line references are regenerated by
`node docs/scripts/resolve-refs.mjs` from `path#symbol` anchors so they stay accurate.

## 1. Assets and security goals

| Goal | Definition |
|---|---|
| **Eligibility** | Only commitments on the registrar-published roll can produce accepted ballots. |
| **Uniqueness** | Each roll entry contributes at most one counted ballot (last-vote-counts). |
| **Ballot secrecy** | No party below the trustee threshold learns the content of an individual ballot. No party learns which roll entry cast which ballot. |
| **Individual verifiability** | A voter can confirm the ballot they cast is the one aggregated. |
| **Universal verifiability** | Anyone can recompute the result from public data alone. |
| **Cast-as-intended** | A voter can detect a client that encrypts something other than their choice. |
| **Availability** | No single operator can silently stop votes from being accepted. |

## 2. Actors and trust assumptions

| Actor | Trusted for | Not trusted for |
|---|---|---|
| Registrar | Deciding eligibility correctly (out of scope of cryptography) | Learning votes, forging ballots, altering the tally |
| Trustees (n, threshold t) | At least `t` honest and available for tallying | Any `< t` coalition cannot decrypt |
| Election admin | Configuring candidates/schedule before Registration | Anything after Registration starts |
| Relayer | Nothing (fully untrusted; any party can relay) | Censorship is mitigated, not prevented |
| Chain | Liveness and consensus safety (standard EVM assumptions, finality after reorg depth) | — |
| Voter client | Mitigated by Benaloh challenge | Full malware compromise of the device |
| Upgrade authority (timelock + Safe) | Not abusing upgrades between elections | Cannot upgrade during an election (enforced) |

Cryptographic assumptions: discrete log / DDH on Baby Jubjub; Groth16 knowledge soundness under the
Generic Group Model with a secure phase-2 ceremony (≥ 1 honest contributor); Poseidon collision/preimage
resistance; keccak256 as a random oracle for Fiat–Shamir.

## 3. STRIDE analysis

| ID | Threat | Category | Mitigation | Where |
|---|---|---|---|---|
| S-1 | Attacker forges a ballot without being on the roll | Spoofing | Groth16 Merkle-membership proof against the snapshotted root | `contracts/src/Election.sol#castVote`, `circuits/src/ballot.circom#template Ballot` |
| S-2 | Attacker impersonates a trustee in DKG or decryption | Spoofing | Trustee actions authorised by registered account; verification keys derived from commitments | `contracts/src/TrusteeCoordinator.sol#onlyTrustee`, `contracts/src/Tally.sol#submitPartialDecryption` |
| S-3 | Relayer swaps the ciphertext of a relayed ballot | Spoofing/Tampering | Ciphertext is a public input of the proof; verification fails on any change | `contracts/src/Election.sol#castVote` |
| T-1 | Admin edits candidates/schedule after voting starts | Tampering | Mutators gated to `Setup` | `contracts/src/Election.sol#setCandidates`, `contracts/src/Election.sol#setSchedule` |
| T-2 | Registrar changes the roll mid-vote | Tampering | Root snapshotted at `Voting` start; registry writes limited to `Registration` | `contracts/src/Election.sol#_enterVoting`, `contracts/src/VoterRegistry.sol#publishRoot` |
| T-3 | Aggregator omits or duplicates ballots | Tampering | Strictly increasing nullifiers; hash check against stored record; decryption blocked until `aggregated == ballotCount` | `contracts/src/Tally.sol#aggregate`, `contracts/src/Tally.sol#submitPartialDecryption` |
| T-4 | Trustee publishes a wrong partial decryption | Tampering | Chaum–Pedersen proof verified on-chain | `contracts/src/Tally.sol#submitPartialDecryption`, `contracts/src/libraries/ChaumPedersen.sol#verify` |
| T-5 | Finaliser submits a wrong count | Tampering | `count·G == M` verified on-chain; `Σ counts == ballotCount` | `contracts/src/Tally.sol#finalizeSlot`, `contracts/src/Tally.sol#_finalizeElection` |
| T-6 | Upgrade changes code during an election | Tampering | Election upgrades only in `Setup`; singleton upgrades only with zero active elections; timelock | `contracts/src/Election.sol#_authorizeUpgrade`, `contracts/src/VoterRegistry.sol#_authorizeUpgrade`, `contracts/src/Tally.sol#_authorizeUpgrade`, `contracts/src/TrusteeCoordinator.sol#_authorizeUpgrade` |
| T-7 | Pause used to alter results or shorten voting | Tampering | Pause touches no ballot/tally storage; voting end extended by paused time (invariant test) | `contracts/src/Election.sol#_unpause`, `contracts/test/invariant/PauseInvariant.t.sol#invariant_pauseNeverChangesResults` |
| R-1 | Registrar denies having added/removed a commitment | Repudiation | Leaves emitted on-chain; hash-chained audit log in the registrar | `contracts/src/VoterRegistry.sol#publishRoot`, `services/registrar/src/audit/audit-log.service.ts#append` |
| R-2 | Trustee denies having dealt bad shares | Repudiation | Complaint/justification on-chain with verifiable equations | `contracts/src/TrusteeCoordinator.sol#justify` |
| I-1 | Ballot content read from chain | Info disclosure | Exponential ElGamal under a threshold key; no single key holder exists | `circuits/src/lib/elgamal.circom#template ElGamalEncrypt`, `contracts/src/TrusteeCoordinator.sol#finalize` |
| I-2 | Link ballot to voter identity via on-chain data | Info disclosure | ZK membership proof; nullifier is `Poseidon(sk, electionId)`, unlinkable across elections | `circuits/src/ballot.circom#template Ballot` |
| I-3 | Link ballot to voter via gas payer | Info disclosure | Relayer pays gas; any relayer, or direct submission, is accepted | `services/relayer/src/relay.service.ts#relay` |
| I-4 | Registrar learns which leaf a voter proves from the Merkle-proof request | Info disclosure | Client downloads the full leaf list and builds the path locally (default); the per-leaf endpoint is opt-in and documented as leaking | `apps/voter/src/lib/merkle.ts#buildLocalPath` |
| I-5 | Trustee share leaked from disk | Info disclosure | Share encrypted at rest with Argon2id-derived key, AES-256-GCM; optional HSM wrapping | `services/trustee-cli/src/keystore/file-keystore.ts#encrypt`, `services/trustee-cli/src/keystore/pkcs11-keystore.ts` |
| D-1 | Relayer censors ballots | DoS | Direct `castVote` path is permissionless; multiple relayers; voter app exposes "submit from wallet" | `contracts/src/Election.sol#castVote`, `apps/voter/src/app/[locale]/vote/cast-panel.tsx#submitDirect` |
| D-2 | Pause used to block voting indefinitely | DoS | Pause extends the window; pauser cannot finalise or abort; abort conditions are objective | `contracts/src/Election.sol#_unpause`, `contracts/src/Election.sol#abort` |
| D-3 | Trustees refuse to decrypt | DoS | Threshold `t < n`; objective `Aborted` after `tallyDeadline`; alerting on trustee non-response | `contracts/src/Election.sol#abort`, `infra/observability/prometheus/alerts.yml` |
| D-4 | Proof-generation griefing of the relayer (invalid proofs) | DoS | Relayer verifies proofs off-chain before paying gas; rate limits per IP | `services/relayer/src/relay.service.ts#relay` |
| D-5 | Chain reorg drops a ballot | DoS | Relayer resubmits until `confirmations` deep; indexer rolls back on reorg; metric `verivote_chain_reorgs_total` | `services/relayer/src/submitter.ts#waitFinal`, `services/indexer/src/indexer.ts#handleReorg` |
| E-1 | Pauser escalates to altering results | Elevation | Pauser role has no write path into tally/ballot storage (formally checked) | `contracts/test/formal/PauseHalmos.t.sol#check_pauseCannotMutateResults` |
| E-2 | Compromised timelock executor upgrades singletons | Elevation | Timelock delay + multisig; upgrades blocked while elections are active | `contracts/src/VeriVoteFactory.sol#activeElections` |
| E-3 | Reentrancy through verifier or external call | Elevation | No value transfers; checks-effects-interactions; `nonReentrant` on all state-changing externals that call out | `contracts/src/Election.sol#castVote`, `contracts/src/Tally.sol#aggregate` |

## 4. Voting-specific threats

### V-1 Coercion and vote buying

**Partially mitigated. Stated limits below.**

* *Re-voting with last-vote-counts* (`contracts/src/Election.sol#castVote`): a voter who cast under duress can
  cast again privately; only the last ballot is aggregated. This defeats a coercer who observes the voter
  only at casting time.
* *Not resisted*: a coercer who learns the voter's nullifier (by watching the coerced cast) can see on-chain
  that a later ballot was cast under the same nullifier, and can therefore detect re-voting (not its content).
  A coercer who holds the voter's `sk` can cast at any time and detect any re-vote.
* *Not resisted*: a voter can prove how they voted by revealing `(m, r)` for their final ballot, since the
  ciphertext is public (receipt-freeness is **not** provided). This is the same limitation as Helios; MACI-style
  key-change coercion resistance is out of scope and is discussed in the paper.
* Elections may disable re-voting (`allowRevote = false`) where last-vote-counts is undesirable.

### V-2 Ballot stuffing

Mitigated. Every ballot needs a Merkle membership proof and each leaf yields exactly one nullifier
(`circuits/src/ballot.circom#template Ballot`). A registrar inserting fake leaves is a registrar
compromise (V-5), detectable because every leaf is public.

### V-3 Trustee collusion below threshold

Mitigated. Pedersen VSS keeps the secret information-theoretically hidden from `< t` trustees during
dealing; after the Feldman reveal, learning `x` from `< t` shares requires solving DL. Partial decryptions are
of the *aggregate* only. (`contracts/src/TrusteeCoordinator.sol#deal`, `contracts/src/Tally.sol#submitPartialDecryption`)

### V-4 Trustee collusion at or above threshold

**Not mitigated by cryptography.** A coalition of `≥ t` trustees can decrypt individual ballots (ciphertexts are
public). They cannot link ballots to identities (I-2) and cannot alter the tally (T-4, T-5). Operational
mitigation: trustees are chosen from mutually distrusting organisations (RUNBOOK §2).

### V-5 Registrar compromise

**Partially mitigated.** A compromised registrar can add ineligible commitments or exclude eligible voters.
Detection: all leaves are on-chain (`contracts/src/VoterRegistry.sol#publishRoot`), the audit log is
hash-chained (`services/registrar/src/audit/audit-log.service.ts#append`) and the audit CLI
rebuilds the tree (`tools/verivote-audit/src/checks/roll.ts#checkRoll`). Observers must compare the leaf set
against an independent eligibility source; the protocol cannot do that. The registrar never learns `sk` and
cannot vote on a voter's behalf.

### V-6 Relayer censorship

Mitigated (D-1). The relayer has no privileged position; direct submission is always open and the UI exposes it.

### V-7 Client malware

**Partially mitigated.** Benaloh cast-or-audit (`apps/voter/src/app/[locale]/vote/cast-panel.tsx#audit`,
`tools/verivote-audit/src/commands/challenge.ts`) detects a client that encrypts a different choice. A client
that also exfiltrates `sk` or shows a fake receipt is not detected; the verify-my-vote page should be used from
a second device.

### V-8 Chain reorgs

Mitigated (D-5). Finality is defined as `confirmations` blocks in services; the contract state is the source
of truth after finality. Phase transitions depend only on block timestamps, so a reorg cannot reorder phases.

### V-9 Front-running / replay of `castVote`

Mitigated. The proof binds nullifier, ciphertext and `voteIndex`; a front-runner can only submit the identical
ballot earlier (same outcome). Replay of a previous ballot after a re-vote fails because `voteIndex` must equal
the stored count (`contracts/src/Election.sol#castVote`; test
`contracts/test/Election.t.sol#test_frontRunCannotAlterOrReplay`).

### V-10 Malicious proving key / ceremony

Mitigated given one honest contributor. The ceremony script verifies every contribution
(`circuits/scripts/ceremony.sh`) and the verifier is regenerated from the final zkey in CI, failing the build
if it differs from the committed verifier (`.github/workflows/ci.yml` job `circuits`).

### V-11 DKG biasing (Gennaro et al. attack)

Mitigated. Pedersen commitments hide the contributions until `QUAL` is fixed. A `QUAL` member that then
misbehaves in the reveal phase is exposed by a verifiable complaint and the DKG aborts
(`contracts/src/TrusteeCoordinator.sol#exposeReveal`). Residual: the attacker can force a restart (a
publicly attributable DoS), not a biased key.

### V-12 Timing side channels in the voter client

**Not mitigated.** Proof generation time depends on the device, not the vote; witness generation uses
constant-shape arithmetic but no claim is made about memory-access patterns in the browser.

## 5. Out of scope

* Eligibility decisions themselves (KYC correctness).
* Denial of service against the chain.
* Compromise of the voter's device beyond what the Benaloh challenge detects.
* Legal/regulatory requirements for binding public elections.

## 6. Residual risk summary

| Risk | Severity | Owner |
|---|---|---|
| Coercer detects re-vote via nullifier | Medium | Documented; election operators choose `allowRevote` policy |
| `≥ t` trustees decrypt individual ballots | High (secrecy) | Operational trustee selection |
| Registrar roll manipulation | High (eligibility) | External observation of leaf set |
| No receipt-freeness | Medium | Design choice; see paper |
